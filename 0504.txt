2026-05-04 DriftProbe refactor prep notes

Context
- Added the preflight decision checklist to DriftProbe_Refactor_Plan_v2.md.
- Started the first six infrastructure changes that do not depend on the concrete E02 transcript.

Implemented
1. Generic case loader
   - src/runner/run_case.py now scans cases/**/*.yaml by case_id.
   - Removed the hard-coded A01/B01/C01/D01 path mapping.
   - Duplicate case_id values now raise an explicit error.

2. New case spec field compatibility
   - Runner and report can now tolerate new fields such as:
     phenomenon, seed_scenario, observation_focus, transition_windows, extension_metrics.
   - Existing old case specs remain valid.

3. Fixed-script runner path
   - If a case spec contains interaction_script, runner executes those user turns directly.
   - Supported step forms:
     - plain string
     - dict with user_message, message, or content
   - Optional per-step metadata such as action, note, state_before, state_after is carried into transcript entries.

4. Adapter capability skeleton
   - BaseChatAdapter now exposes provider_name, model_name, supports_stream, supports_tools, supports_search, supports_reasoning_summary, and metadata.
   - OpenAILikeAdapter and TransformersLocalAdapter set conservative default capability values.

5. Observations compatibility
   - run_single_case now returns observations in addition to the old turn_labels field.
   - Scripted phase4 turn judge outputs are mirrored into observations with unit=turn.
   - transition_windows from case specs are mirrored into observations with unit=transition and source=case_spec.

6. Core + extension scorer entry
   - compute_case_metrics keeps old core metrics.
   - It now accepts extension_metrics.
   - correction_uptake_score maps to turn label correction_uptake.
   - prior_frame_persistence_rate maps to turn label prior_frame_persistence.
   - Unknown extension metrics return None instead of breaking the pipeline.

7. Report compatibility
   - Markdown reports can show phenomenon summary, observation focus, transition windows, and extension metrics.
   - Missing extension metric values render as n/a.

Actor/Judge API provider refactor
- Design decision:
  - Target remains the experiment variable and continues to use OpenRouter or any target provider selected by RunConfig.
  - Actor and Judge are fixed evaluation infrastructure.
  - Actor/Judge now come from configs/models.yaml roles, not from per-target CLI arguments.
  - Actor/Judge are configured to use the DeepSeek official API provider, not OpenRouter.
- configs/models.yaml:
  - Added roles.actor and roles.judge.
  - Added provider deepseek with kind=openai_compatible, base_url=https://api.deepseek.com, api_key_env=DEEPSEEK_API_KEY.
  - roles.actor and roles.judge currently point to provider=deepseek, model=deepseek-v4.
  - The DeepSeek model ID is intentionally config-level and can be adjusted to the exact non-flash v4 model ID exposed by the DeepSeek account.
- src/adapters/router.py:
  - Provider construction now supports arbitrary providers with kind=openai_compatible.
  - Missing provider API keys are skipped instead of failing unrelated runs.
- src/adapters/openai_like.py:
  - OpenAILikeAdapter now accepts provider_name and default_model.
  - Response provider is no longer hard-coded to openrouter.
- src/actor/engine.py and src/judge/engine.py:
  - ActorConfig and JudgeConfig now include provider.
  - Requests use config.provider instead of hard-coded local/transformers.
- src/runner/run_case.py:
  - Reads fixed actor/judge role config from configs/models.yaml.
  - Phase 3 uses roles.actor.
  - Phase 4 uses roles.actor and roles.judge.
  - Scripted Phase 4 uses roles.judge only.
  - Missing role adapters now produce role-specific error messages.
- scripts/run_model_suite.py:
  - Fixed phase argument propagation into RunConfig.
- Validation:
  - py_compile passed for the changed Python files.
  - conda run -n city-marl python scripts/smoke_e01_scripted_flow.py still passes without network/API/model loading.
